# 评测报告模板（M0）

版本：v0.1 · 适用：M0 原型验证阶段

> 每次跑评测按本模板填写。目标：让人类验收者**不需要看代码、不需要懂算法**，就能按本模板逐项独立判断第 5 节每项指标通过与否。每个数字必须注明数据来源是「真实 KTV 录音」还是「模拟样本」，模拟结论不得作为验收通过依据。

## 3. 逐项实测值（必填）

对第 5 节每项指标给出：**测量方法 + 样本口径 + 统计量 + 实测值 + 通过/不通过**。统计量统一用「中位数 + P90 + 最大值」或「百分比」，不只用均值。

### 3.1 首次识别耗时（目标 < 5s）

- 测量方法：从样本起播到识别结果首次超过置信阈值（`song_id` + `confidence`）的时间差；只统计「有旋律段起播」样本，纯前奏起播样本单列（见 `RISKS.md` R1）。
- 样本口径：真实录音 + 合成样本分别统计。
- 统计量：中位数、P90、最大值、超 5s 占比。
- **通过条件：中位数 < 5s 且 P90 < 5s。**
- 实测：`__` → 通过 / 不通过

### 3.2 识别准确率（曲库内 Top-1 > 95%；曲库外明确返回未识别）

- 曲库内：Top-1 准确率（正确 `song_id` 占比）；附 Top-1 混淆矩阵。
- 曲库外：误识率（被识别为某首歌的占比，应趋近 0）、拒识率（明确返回未识别的占比）。
- 统计量：百分比。
- **通过条件：曲库内 Top-1 ≥ 95%；曲库外误识率 ≤ 5%（建议值，待队长确认）且拒识率 ≥ 95%。**
- 实测：`__` → 通过 / 不通过

### 3.3 初始定位误差（目标中位数 < 200ms）

- 测量方法：识别成功样本的 `|预测 offset − 真值 offset|` 绝对误差。
- 样本口径：真实录音 + 合成样本分别统计。
- 统计量：中位数、P90、最大值（ms）。
- **通过条件：中位数 < 200ms。**
- 实测：`__` → 通过 / 不通过

### 3.4 持续同步（整曲无需手动干预、无可见歌词跳动）

- 测量方法：整曲回放，按 `UI_SPEC.md` 第 3.2 节记录行号时间序列并判定；同时记录全程是否出现手动干预。
- 统计量：行切换误差中位数 / P90、违规行数占比、手动干预次数（应为 0）。
- **通过条件：全程 0 次手动干预，且不出现 `UI_SPEC.md` 3.2 任何「不可接受」条目。**
- 实测：`__` → 通过 / 不通过

### 3.5 暂停 / 重唱 / 切歌恢复（自动恢复，恢复后 3s 内重新对齐）

- 测量方法：构造对应事件样本，记录「事件发生 → 重新对齐（`|offset 误差| < 200ms` 或识别恢复）」的耗时。
- 样本口径：真实录音事件样本 + 合成事件样本。
- 统计量：恢复时间中位数 / P90、3s 内对齐成功率。
- **通过条件：全部自动恢复（0 手动干预），且恢复时间中位数 < 3s。**
- 实测：`__` → 通过 / 不通过

### 3.6 变调变速鲁棒性（±1 半音、±5% 变速；决定是否切 Panako）

- 测量方法：合成样本（变调 ±1 半音、变速 ±5%）上的识别率 + 定位误差。
- 统计量：Top-1 准确率、定位误差中位数。
- **结论口径（建议，待队长确认）：变调 ±1 半音 或 变速 ±5% 下 Top-1 < 90% 或定位误差中位数 > 500ms → 启动 Panako 切换评估。**
- 实测：`__` → 维持 Shazam 方案 / 启动 Panako 评估
