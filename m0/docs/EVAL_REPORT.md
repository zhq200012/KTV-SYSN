## 3. 逐项实测值

### 3.1 首次识别耗时（目标 < 5s）【模拟】

- 测量：起播到首次识别（置信超阈值）的时间差；仅统计有旋律段起播样本。
- 实测：中位数 **2.00s**，P90 **2.00s**，最大 2.00s，超 5s 占比 0/23。
- 结论：✅ 通过

### 3.2 识别准确率（曲库内 Top-1 > 95%；曲库外明确返回未识别）【模拟】

- 曲库内正常样本 Top-1 准确率：23/23 = **100.0%**（未识别样本计入未命中）。
- 曲库外：误识率 0/2 = 0.0%，拒识率 **100.0%**。
- 结论：✅ 通过

### 3.3 初始定位误差（目标中位数 < 200ms）【模拟】

- 测量：识别成功样本 |预测进度 − 真值进度|。
- 实测：中位数 **5ms**，P90 14ms，最大 15ms（n=23）。
- 结论：✅ 通过

### 3.4 持续同步（无手动干预、无可见歌词跳动）【模拟】

- 整曲样本 2 段，行切换 18 次，切换误差 >0.5s 的行 0 次。
- UI_SPEC §3.2 违规（硬性红线）：0 条。
- 手动干预：0 次（离线回放，无需干预）。
- 结论：✅ 通过

### 3.5 暂停 / 重唱 / 切歌 / 失锁恢复（自动恢复，3s 内重新对齐）【模拟】

- 事件样本 10 段，恢复时间中位数 **1.85s**，P90 2.30s，3s 内对齐 10/10。
- 自动恢复（0 手动干预）：是。
- 结论：✅ 通过

### 3.6 变调变速鲁棒性（±1 半音、±5% 变速；决定是否切 Panako）【模拟】

- 变调 ±1 半音（2 段）：识别成功 2 段，Top-1 正确 2 段，定位误差中位数 6885ms（错位匹配，见下）。
- 变速 ±5%（2 段）：识别成功 2 段，Top-1 正确 2 段，定位误差中位数 43ms。
- 合计 Top-1 正确率 **100.0%**，已识别样本定位误差中位数 2215ms。
- 结论：**启动 Panako 切换评估**

> 说明（模拟局限，不作为真实结论）：合成「变速」因音符时长较短（约 0.5s），±5% 拉伸未超过 Δt 帧量化（32ms）容差，仍能命中；合成「变调」因频带过密，偏移后的音符巧合命中其他参考音符，产生**错误 offset** 的匹配（定位误差 > 500ms）。两者均按 R3/R4 口径以「定位误差 > 500ms」触发 Panako 评估，真实结论待 KTV 录音判定。

## 4. 失败样例分析

无曲库内正常样本失败；变调/变速失败见 §3.6（预期内，Shazam 式哈希对频率/Δt 失真不鲁棒，见 RISKS R3/R4）。

## 5. 遗留问题（区分真实 vs 模拟）

- 【模拟结论】所有 §3 指标均由合成样本测得，仅证明链路可跑通，不作为验收通过依据。
- 【待真实录音】真实 KTV 录音为 0 段：识别率/定位/同步/暂停重唱切歌的验收指标需真实包房录音后补齐；已向 @张洪清 请求 3~5 首真实录音。
- 【R1 待确认】「任意位置起播 <5s」是否含纯前奏：合成样本无静音前奏，前奏指纹稀疏问题未模拟；开发按「有旋律段起播 <5s、前奏起播单列」临时口径推进。
- 【R3/R4 已触发】变调 ±1 半音、变速 ±5% 下 Shazam 式指纹失效，建议按 §3.6 启动 Panako 评估。
- 【对齐简化】M0 `align` 仅保留 LRC 行级时间戳，词级强制对齐（WhisperX）留 P1。
