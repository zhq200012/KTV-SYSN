# 终端跟唱界面规范（M0）

版本：v0.1 · 适用：M0 原型验证阶段 · 呈现媒介：终端（TTY）

> 本规范定义 M0「歌词渲染」层的呈现契约。开发照此实现 `timeline.py` 的终端渲染，验收者照第 3 节独立判断「无可见歌词跳动」是否达标。逐字扫字为 P1，本规范只给接口约定、不要求 M0 实现。

## 0. 适用范围

- M0 用**终端文本输出**呈现跟唱界面（DESIGN.md 4.2：歌词演示 = 终端输出或极简桌面 UI，逐行高亮即可）。
- 若开发选用极简桌面 UI，布局可替换，但**颜色 / 层级 / 行状态 / 判定标准**复用本规范，不得另起一套。
- 目标不是产品 UI，而是让「识别 → 定位 → 持续同步 → 歌词渲染」链路能被看清、能被验收。

## 1. 屏幕布局

固定分区（自上而下），行号固定，避免内容漂移：

```
┌──────────────────────────────────────────────┐
│ ① [状态行] 跟唱中 · 歌曲标题 · 0:42.3 / 3:12.0 │
│ ───────────────────────────────────────────── │
│ ②   上一行歌词（暗色）                         │
│    ▶ 当前行歌词（高亮加粗）                    │
│     下一行歌词（暗色）                         │
│ ───────────────────────────────────────────── │
│ ③ [和弦]  C ──▶ G   (0.4s)                    │
│ ④ [倒数]  3 · 2 · 1 · 进                       │  仅前奏/间奏出现
│ ───────────────────────────────────────────── │
│ ⑤ [提示] 未识别到歌曲                          │  诊断/事件提示，空闲时留空
└──────────────────────────────────────────────┘
```

| 分区 | 行数 | 说明 |
|---|---|---|
| ① 状态行 | 1 | 状态 + 歌曲标题 + 进度时间 `当前/总长` |
| ② 歌词窗口 | 3 | 上一行 / 当前行 / 下一行，当前行固定居中 |
| ③ 和弦行 | 1 | 当前和弦 → 下一和弦 + 剩余秒数；无和弦留空 |
| ④ 倒数行 | 1 | 仅前奏/间奏进唱前 3s 显示，其余留空 |
| ⑤ 提示行 | 1 | 状态/事件提示（识别中、未识别、切歌、重唱、失锁），空闲留空 |

## 2. 歌词行三种状态与视觉区分

| 行类型 | 前缀 | ANSI（可配置） | 说明 |
|---|---|---|---|
| 已唱行 | ` `（2 空格） | `\x1b[2;90m`（dim + 亮黑） | 已唱完、滚出当前焦点 |
| 当前行 | `▶ ` | `\x1b[1;93m`（bold + 亮黄） | 正在跟唱 |
| 下一行 | ` `（2 空格） | `\x1b[2;37m`（dim + 白） | 即将唱到 |

颜色约定（ANSI 8/16 色，保证兼容，具体色值可配置，但**层级关系固定**：当前行 > 下一行 > 已唱行）：

| 元素 | 建议色 |
|---|---|
| 当前行 | bold + 亮黄（93）或亮白（97） |
| 已唱行 / 下一行 | dim + 灰（90）/ dim + 白（37） |
| 和弦-当前 | 亮绿（92） |
| 和弦-预告 | 亮青（96） |
| 倒数最后 1s | bold + 亮红（91） |
| 状态：识别中 | 黄（33） |
| 状态：跟唱中 | 绿（32） |
| 状态：未识别 / 失锁 | 红（31） |
| 状态：暂停 | 灰（90） |

## 3. 滚动节奏与「无可见歌词跳动」判定标准

### 3.1 滚动规则

- 歌词窗口固定 3 行，**当前行固定在中间行，位置不动**。
- **行切换只发生在行边界**（当前行 `end` 时刻）：整体上移一行（上一行滚出、当前行变已唱、下一行变当前）。
- 渐进校正（偏差 100ms~1s，见 DESIGN 3.3）期间，**只在行内平滑追赶进度，不触发行切换**；校正不改变行号、不改变切换方向。
- 前奏 / 间奏（无歌词段落）内允许整段无当前行，进唱行在倒数结束时准时出现。

### 3.2 「无可见歌词跳动」判定标准（验收口径）

整曲回放测试中，渲染器每个重绘 tick 记录一次「当前行行号」，得到行号时间序列，按下列规则判定。**出现任意一条「不可接受」，该项验收即判不通过**：

**可接受（全部满足）：**

1. **单调向前**：行号序列单调不减，每次变化 `+1`（不跳行）；合法「重唱」事件（见第 5 节）是唯一允许行号回退的场景。
2. **切换时机**：行号从 `n` 变 `n+1` 的时刻 `T` 满足 `|T − line[n+1].start| ≤ 0.5s`（P0 行切换误差容差，DESIGN 1.2）。
3. **稳定**：任意 1 秒窗口内行号变化 ≤ 1 次（不来回抖）。
4. **重唱例外**：行号回退仅允许发生在「重唱」事件后的 2s 内，且必须伴随「重唱」提示。

**不可接受（出现即失败）：**

1. 行号回退（当前行又变回已唱行），且不属于「重唱」例外。
2. 跨行跳变（行号 `+2` 及以上）。
3. 同一行 1 秒内切换 2 次及以上（来回抖）。
4. 已唱行重新高亮超过 1 次（不计「重唱」例外）。
5. 行切换误差 `> ±0.5s` 的行数占整曲总切换次数比例 `> 5%`。

> 说明：上述 1~4 为「硬性红线」，第 5 条为「比例容忍」。开发可把 3.2 的判定写成 `eval` 脚本自动统计，同时保留人工复核入口。

## 4. 和弦预告

- 数据源：`timeline.json` `lines[].chords[]`（`t` + `name`）。
- 展示：和弦行显示「当前和弦 → 下一和弦 + 剩余秒数」。
- **提前量：默认 0.5s**（覆盖 BPM 60~120 下「半拍到一拍」的中间值；时间轴当前无 BPM 字段，见 `RISKS.md` R9）。
- 切换：到 `chords[].t` 时刻，当前和弦替换为下一和弦，预告区更新为再下一个。
- 无和弦信息时该行留空，不显示占位符。

## 5. 前奏 / 间奏进唱倒数

- 数据源：`timeline.json` `sections[]`（`type=intro` / `type=interlude`，含 `start` / `end`）。
- 展示：在段落 `end` 前 3s 开始倒数 `3 → 2 → 1 → 进`（或「唱」），每秒一跳，最后 1s 用 bold + 红色高亮。
- 进唱时刻 = 下一行歌词 `start`；倒数结束的同时，当前行跳到进唱行（合法切行，不属于「跳动」）。

## 6. 状态提示：文案与最短持续时长

状态机来自 DESIGN 3.3；渲染器对状态/事件做**防抖**（状态变化至少保持「最短持续时长」才允许切换显示），避免来回抖。

| 状态 / 事件 | 文案 | 最短持续时长 | 备注 |
|---|---|---|---|
| 识别中 | `识别中…` | 500ms | 低置信未达阈值时保持，不闪 |
| 未识别（低于置信阈值） | `未识别到歌曲` | 2000ms | 明确不猜测 |
| 播放中 | `跟唱中 · <标题>` | 1000ms | 常驻状态行 |
| 暂停 | `已暂停` | 1000ms | 音频能量低且匹配持续失败 |
| 切歌 | `已切歌 · <新标题>` | 2000ms | **事件**：显示 2s 后回落为「跟唱中」 |
| 重唱 | `重唱` | 2000ms | **事件**：offset 回退到开头附近，显示 2s 后回落 |
| 失锁 | `失去同步 · 重新识别中…` | 无上限 | 持续显示直到恢复，后台重试 |

> 「切歌」「重唱」是**瞬时事件**而非持续状态（DESIGN 3.3 把它们建模为「播放中」内部跳转）。`sync_engine` 除状态外需输出这些事件，渲染器消费事件做提示（接口见 `RISKS.md` R6，最终契约写进开发阶段的 `INTERFACES.md`）。

## 7. 终端宽度不足 / 中英混排 / 截断

- **显示宽度**：CJK / 全角字符 = 2 列，ASCII / 半角 = 1 列；按显示列（`wcwidth` 语义）计算，**不按字符数**。
- **单行截断**：超宽时截断到 `COLUMNS − 1` 列，末尾加 `…`（U+2026，宽 1）。只影响显示，不改数据。
- **对齐**：歌词左对齐，前缀 `▶ `/`  `（2 空格）占固定列；不按字符居中。
- **自适应**：每次重绘读取终端宽度（`COLUMNS`），动态重排；宽度 `< 40` 时降级为「仅当前行 + 状态行」两行模式。

## 8. 逐字高亮接口（P1，M0 可不实现）

- 数据：`timeline.json` `lines[].words[]`（`t` + `text`）已在 DESIGN 4.4 定义。
- 接口约定：渲染函数 `render_line(line, position_sec) → 分段`（已唱字 / 当前字 / 未唱字）；M0 返回整行高亮，P1 返回逐字分段。
- **M0 解析 `timeline.json` 时必须保留 `words` / `chords` / `sections` 字段**，不报错、不丢弃，供 P1 直接使用。

## 9. 刷新频率与性能

- 重绘频率 **≥ 10 fps**（推荐 30 fps），由进度时钟驱动，不忙等、不空转。
- 全屏重绘或差分更新均可；终端 ANSI 支持不足时降级为整行刷新。
- 渲染层不得阻塞同步引擎：渲染滞后只影响显示帧率，不影响进度推进。
