# 实现风险清单（M0 设计评审）

版本：v0.1 · 对 DESIGN.md v0.1 中含糊、冲突或明显不可实现处的逐条记录

> 本清单只记录「现象 + 建议」，**不自行改需求**。需要拍板的（阈值、口径）标为「待确认」，由队长 / 人类决定后写回设计文档与开发契约（`INTERFACES.md`）。

| # | 位置（DESIGN.md） | 现象 | 建议 / 待确认 |
|---|---|---|---|
| R1 | §5、§3.1 | 「首次识别 < 5s（从歌曲**任意位置**开始听）」与纯前奏 / 无旋律段落起播冲突：前奏 / 纯鼓 / 无旋律段指纹稀疏，Shazam 式匹配难以 5s 内稳定命中。 | 明确「任意位置」是否含纯前奏起播；若含，前奏起播单独给识别耗时上限；否则指标改为「有旋律段起播 < 5s」，前奏起播另计。**待确认** |
| R2 | §5、§3.2、§4.1 | 「初始定位误差中位数 < 200ms」受 offset 直方图 **bin 宽**制约；DESIGN 未指定 bin 宽，若 ≥ 200ms 则该指标物理上不可达。 | 约定 offset 直方图 bin 宽 ≤ 50ms，峰位用抛物线插值细化；写入开发契约 `INTERFACES.md`。 |

| R5 | §5、§3.3 | 「无可见歌词跳动」是主观指标，且与 §3.3「偏差 > 1s 直接跳转」冲突：跳转本身即可见跳动，两者未说明何时跳转可接受。 | 已由 `UI_SPEC.md` §3.2 给出量化判定（行号单调、±0.5s 容差、禁止回退/抖行），并把「跳转」限定为切歌 / 重唱等合法场景；`sync_engine` 须保证正常校正不累积到 > 1s。请队长确认该判定为验收口径。 |
| R6 | §3.3、§6 | 状态机无「切歌 / 重唱」独立状态（建模为「播放中」内部跳转），但 UI 要求给切歌 / 重唱提示文案。 | `sync_engine` 除状态外需输出瞬时**事件**（切歌 / 重唱 / 恢复），渲染器消费事件做提示；事件与状态的接口写入 `INTERFACES.md`。 |
| R7 | §3.3 | `captured_at` 延迟补偿依赖真实采集时钟，M0 离线**文件回放**没有真实采集时钟，该补偿无法按真实语义离线验证。 | 文件回放用「文件内时间戳」模拟 `captured_at`，实时麦克风用 wall clock；统一 timestamp 来源接口，使延迟补偿可离线单测。 |
| R8 | §5、§3.1 | 「低于阈值返回未识别」但阈值如何标定、误识率 / 拒识率目标未定义，无法独立验收「曲库外明确返回未识别」。 | 测试集须含曲库外样本；报告须给误识率（曲库外误判）/ 拒识率（曲库内误拒）两项；阈值标定方法写入评测模板。建议：误识率 ≤ 5% 且曲库内 Top-1 ≥ 95% 同时满足。**阈值待确认** |

## 附：不改变需求的原则

以上建议均不扩大产品范围（不新增打分 / 点歌 / 手机端 / 云端）。涉及指标口径的（R1、R3、R8）在队长 / 人类确认后，由开发写入 `INTERFACES.md` 与评测脚本，设计文档不再单方面改动。
